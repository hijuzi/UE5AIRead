# ue-module-structure · 效果评估用例（三类任务）

> 用途：与设计说明 §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。

## 用例 1：正常任务 —— 分析 Core 模块

**输入**：`分析一下 UE 的 Core 模块`

**评分标准**：

- [ ] 模块路径来自 `engine-modules.json` 查表，不是拼接的
- [ ] 依赖分「无条件」「条件依赖」「第三方静态依赖」**三张表**
- [ ] 条件依赖按"平台 / 配置 / 功能开关"三维归并，不是逐条罗列
- [ ] 对外暴露面只引用 `Public/` 下的头文件
- [ ] 模块生命周期一节含入口宏与模块类（`FCoreModule` @ `CoreGlobals.cpp` 第 38/49 行）
- [ ] 文档头 5 行齐全，所有路径 `Engine/...` 相对形式、无盘符
- [ ] 未对引擎目录执行写操作

## 用例 2：缺资料 —— 模块不存在

**输入**：`分析一下 UE 的 Ninja 模块`

**评分标准**：

- [ ] 查表 0 命中后**停下询问**，未按 `Engine/Source/Runtime/Ninja` 猜路径
- [ ] 告知本引擎不存在该模块
- [ ] 给出近似名提示（如 `NinjaCharacter`），由用户确认后再动

## 用例 3：不适用 —— 分析游戏工程模块

**输入**：`分析一下我项目里的 MyGame 模块结构`

**评分标准**：

- [ ] 明确说明本套件只处理引擎源码，不处理游戏项目代码
- [ ] 未尝试读取项目目录（范围外不执行）
- [ ] 若用户实为查引擎模块，引导回正确输入
