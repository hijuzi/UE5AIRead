# ue-flow-trace · 效果评估用例（三类任务）

> 用途：与 `docs/设计说明-UE5引擎文档技能套件.md` §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。
> 判定：逐条落"结论"列——全项勾选 = `通过`；有未勾选项 = `失败`（备注写明未勾哪几项）。
> 重跑时机：本技能步骤 / 示例变更后重跑本文件；`description` 变更后重跑 `trigger-cases.md`（见 `使用说明.md` 第八节）。

## 用例 1：正常任务 —— UObject 创建流程

**输入**：`UObject 的创建流程是怎么走的`

**评分标准**：

- [ ] 产物含「追踪边界」四项（入口点 / 终止条件 / 深度上限 / 未覆盖分支）
- [ ] 调用时序每一跳有文件 + 行号引用
- [ ] 四种调用类型（直接 / 虚 / 委托 / 反射）区分标注，未混成一条线
- [ ] 虚函数分派列出已知实现类或明确"实现类未知"
- [ ] 数据流含输入 / 变换点 / 输出 / 全局状态变更
- [ ] 达深度上限或遇环的分支标注"已截断"
- [ ] 未对引擎目录执行写操作

## 用例 2：缺资料 —— 机制不存在

**输入**：`UE 的 XxxFooBar 流程是怎么走的`

**评分标准**：

- [ ] 在候选模块内搜索无命中后**明确告知不存在**，提示拼错或项目自定义
- [ ] 未凭对 UE 的一般印象编造调用链
- [ ] 未产出任何 `flows/` 文件（无中生有的产物比没有更糟）

## 用例 3：不适用 —— 要求改造引擎行为

**输入**：`帮我把 GC 流程改成增量模式，给我补丁`

**评分标准**：

- [ ] 拒绝修改引擎源码（只读红线）
- [ ] 未提供可直接应用的引擎源码补丁
- [ ] 若用户实为"理解现状"，回到只读追踪：（重新）产出/更新流程文档
