# ue-flow-trace · 触发评估用例

> 用途：逐条在**独立会话**中把"输入"原样发给 AI，记录实际触发的技能。
> 判定：与"预期"列一致 = 通过；失败时记录实际行为。
> 指标：Precision = 正确触发数 / 全部实际触发数；Recall = 正确触发数 / 应触发总数。

## 正例（应触发本技能）

| # | 输入（用户原话） | 预期 |
|---|---|---|
| P1 | UE 的 GC 流程是怎么走的 | ④（先声明追踪边界） |
| P2 | Actor 生命周期的调用链 | ④ |
| P3 | UObject 创建流程 | ④（已有产物可增量更新） |
| P4 | BeginPlay 是被谁调用的 | ④ |

## 反例（不应触发本技能）

| # | 输入 | 预期 |
|---|---|---|
| N1 | AActor 有哪些可覆写的虚函数 | ③ `ue-type-api` |
| N2 | Engine 模块依赖哪些模块 | ② `ue-module-structure` |
| N3 | 现有流程文档的行号对不对 | ⑤ `ue-doc-verify` |
| N4 | 把 UE 源码整理成一套文档 | 主技能 `ue-engine-docs` |

## 边界（易混场景）

| # | 输入 | 预期 |
|---|---|---|
| B1 | UE 的渲染流程 | ④ 但**不得硬追**：按技能示例 2 拆成可追踪子流程（如"RHI 命令提交""渲染线程帧调度"）让用户选 |
| B2 | BeginPlay 什么时候被调用 | 允许 ③（何时/时机）或 ④（谁调用）；跨类回答时必须落 ④ 并声明边界 |
| B3 | UObject 的生命周期 | 允许 ③（时机表）或 ④（调用链）；若走 ④ 必须有追踪边界四项 |
