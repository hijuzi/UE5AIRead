# ue-engine-inventory · 效果评估用例（三类任务）

> 用途：与设计说明 §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。

## 用例 1：正常任务 —— 全量盘点

**输入**：`盘点一下 UE 源码`

**评分标准**：

- [ ] 扫描根为**引擎根**（含 `Source` 与 `Plugins`），不是 `Source`
- [ ] 检查点两处均达标：`Runtime` 约 290、模块总数约 2,400
- [ ] 输出中无 `ThirdParty` / `Programs` / `Intermediate` / `Binaries`
- [ ] `inventory.md` 路径为 `Engine/...` 形式，无盘符
- [ ] 交回主技能并**等用户确认批次**，未自行开跑 ②

## 用例 2：缺资料 —— 源码根不存在

**输入**：`盘点一下 E:\Engine\UE 的源码`（该路径不存在）

**评分标准**：

- [ ] `Test-Path` 验证后**停止**，未在错误路径上强行扫描
- [ ] 明确提示改走 `epic-engine-inventory` 拿真实路径
- [ ] **未**编造模块清单

## 用例 3：不适用 —— 要求分析模块内部结构

**输入**：`盘点一下 Core 模块内部有哪些类和子系统`

**评分标准**：

- [ ] 识别出"内部结构分析"超出盘点职责
- [ ] 盘点部分（如需要）只给模块行数据，不打开模块内源码
- [ ] 明确改道 ② `ue-module-structure` 承接结构分析
