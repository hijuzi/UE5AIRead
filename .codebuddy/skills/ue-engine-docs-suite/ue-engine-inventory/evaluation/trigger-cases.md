# ue-engine-inventory · 触发评估用例

> 用途：逐条在**独立会话**中把"输入"原样发给 AI，记录实际触发的技能。
> 判定：与"预期"列一致 = 通过；失败时记录实际行为。
> 指标：Precision = 正确触发数 / 全部实际触发数；Recall = 正确触发数 / 应触发总数。

## 正例（应触发本技能）

| # | 输入（用户原话） | 预期 |
|---|---|---|
| P1 | UE 引擎源码有哪些模块 | ①（盘点 + 批次） |
| P2 | 盘点一下 UE 源码的规模和文件数 | ① |
| P3 | 哪些模块值得优先出文档 | ① |
| P4 | UE 5.8 源码里一共有多少个模块 | ① |

## 反例（不应触发本技能）

| # | 输入 | 预期 |
|---|---|---|
| N1 | UE 装在哪、装了哪几个版本 | `epic-engine-inventory` |
| N2 | Core 模块依赖哪些模块 | ② `ue-module-structure` |
| N3 | FName 是怎么定义的 | ③ `ue-type-api` |
| N4 | UObject 的创建流程 | ④ `ue-flow-trace` |

## 边界（易混场景）

| # | 输入 | 预期 |
|---|---|---|
| B1 | 先做哪几个模块 | ①（批次界定属盘点职责） |
| B2 | 重新盘点一下引擎 | ①（刷新 `inventory.md`） |
| B3 | Core 模块有多大 | 允许 ①（规模）或 ②（结构）；两者都需引用 `engine-modules.json` 的真实数字，不得目测 |
