# ue-engine-docs · 触发评估用例

> 用途：逐条在**独立会话**中把"输入"原样发给 AI（不附加任何提示），记录实际触发的技能。
> 判定：与"预期"列一致 = 通过；触发其他技能或未触发 = 失败（失败时记录实际行为）。
> 指标：Precision = 正确触发数 / 全部实际触发数；Recall = 正确触发数 / 应触发总数。
> 目标的技能名以 `ue-` 前缀简写（如"②" = `ue-module-structure`）。

## 正例（应触发本技能）

| # | 输入（用户原话） | 预期 |
|---|---|---|
| P1 | 把 UE5 引擎源码整理成技术文档 | 主技能（先核对环境 → 呈现批次表 → 等确认） |
| P2 | 建一个 UE5 引擎知识库 | 主技能 |
| P3 | UE 源码文档怎么组织比较好 | 主技能 |
| P4 | 帮我梳理一套 UE 引擎源码的文档体系 | 主技能 |

## 反例（不应触发本技能，应路由到子技能）

| # | 输入 | 预期 |
|---|---|---|
| N1 | 分析一下 UE 的 Core 模块 | ② `ue-module-structure` |
| N2 | AActor 是怎么定义的 | ③ `ue-type-api` |
| N3 | UE 的 GC 流程是怎么走的 | ④ `ue-flow-trace` |
| N4 | 校验一下现有文档的行号 | ⑤ `ue-doc-verify` |
| N5 | UE 装了哪些版本、装在哪个目录 | `epic-engine-inventory`（不在本套件，主技能应声明改道） |

## 边界（易混场景）

| # | 输入 | 预期 |
|---|---|---|
| B1 | 帮我看看 UE 源码 | 主技能（笼统兜底；不得直接开读源码） |
| B2 | 整理一下 Core 模块的文档 | ②（含模块名时子技能优先，即使出现"整理/文档"词） |
| B3 | 更新一下文档库的索引 | 主技能（维护动作不属任何子技能） |
| B4 | 把 UObject 相关的都梳理一下 | 允许 ③ 或主技能追问粒度；**必须**在开跑前确认"UObject 相关"指类、流程还是模块 |
