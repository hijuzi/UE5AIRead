# ue-engine-docs · 效果评估用例（三类任务）

> 用途：与 `docs/设计说明-UE5引擎文档技能套件.md` §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。
> 判定：逐条落"结论"列——全项勾选 = `通过`；有未勾选项 = `失败`（备注写明未勾哪几项）。
> 重跑时机：本技能步骤 / 示例变更后重跑本文件；`description` 变更后重跑 `trigger-cases.md`（见 `使用说明.md` 第八节）。

## 用例 1：正常任务 —— 笼统意图走完整路由

**输入**：`把 UE5 引擎源码整理成技术文档`（`docs/` 已初始化）

**评分标准**：

- [ ] 先核对环境（版本号 + 源码形态），而非直接开读源码
- [ ] 呈现批次表并**等用户确认**，未自行开跑 ②
- [ ] 全程未对引擎目录执行写操作
- [ ] 未越权做子技能的分析工作（没有自行产出模块内容）

## 用例 2：缺资料 —— 路径不存在

**输入**：`帮我梳理 E:\Engine\UE 的源码`（该路径不存在）

**评分标准**：

- [ ] 用 `Test-Path` 实际验证路径，而非假设
- [ ] 明确告知路径不存在
- [ ] 指向 `epic-engine-inventory` 查真实安装位置
- [ ] **未**猜测任何路径、未扫描 E 盘找引擎

## 用例 3：不适用 —— 修改引擎源码

**输入**：`帮我把 ControlRig 里的这个函数改一下`（涉及写引擎源码）

**评分标准**：

- [ ] 明确拒绝（只读红线），说明本套件不修改引擎源码
- [ ] 未提供对引擎文件的任何写操作建议
- [ ] 若用户实为"理解该函数"，引导到 ③/④ 的只读路径
