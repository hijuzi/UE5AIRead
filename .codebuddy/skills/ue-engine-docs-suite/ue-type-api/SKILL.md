# UE5 类型与 API 面分析

给定**一个类型**（类 / 结构体 / 接口），产出该类型的继承链、公开 API 与扩展点文档。

## 职责边界

| 本技能负责 | 本技能**不做** |
|---|---|
| 继承链、基类、派生类 | 模块级目录与依赖（→ `ue-module-structure`） |
| 反射宏与模块导出宏 | 跨类调用链、时序、帧流程（→ `ue-flow-trace`） |
| 公开 API 表（函数、属性） | 模块清单盘点（→ `ue-engine-inventory`） |
| 可覆写虚函数（扩展点） | 蓝图节点用法、编辑器操作步骤 |
| 生命周期钩子的**时机** | 生命周期钩子的**完整调用链**（→ `ue-flow-trace`） |

**判断标准**：本技能只描述"这个类型自身是什么、能做什么、能被怎么扩展"。
一旦内容需要跨越两个以上类型才能讲清，属 `ue-flow-trace`。

## 前置条件

`docs/_meta/inventory.md` 与 `docs/_meta/convention.md` 必须存在。
缺失时先跑 `ue-engine-inventory`，再跑主技能初始化。

## 核心约束

1. **先定位文件，再读声明。** 不许凭"常见写法"推断宏、命名空间或基类——UE 的类型既可能在全局命名空间，也可能在 `UE::` 之类的命名空间下，**读原文件确认**。
2. **继承链必须双向。** 只说基类不算完整——但派生类搜索要限定在纳入范围的模块内，并在产物中声明搜索边界，避免让人误以为"没有其他派生类"。
3. **只读。** 不修改引擎任何文件。写入仅限 `docs/types/`。
4. **路径写相对形式。** `Engine/Source/Runtime/Core/Public/CoreTypes.h`，不带盘符。
5. **引用要能被 token 解析。** 三类写法会被 `ue-doc-verify` 判为"引用缺失"，必须规避：
   模块内相对形式（如 `Engine/Classes/...`）、用 `.../` 缩写中间段、路径后紧跟全角括号不设分隔。
   写完后自查这三条；规则原文见 `_meta/convention.md` 第 4.1 节。

## 执行步骤

### Step 1: 定位类型所在文件

**先用模块清单缩小范围**，不要全库乱搜。按类型前缀猜模块：

| 前缀 | 含义 | 优先搜索路径 |
|---|---|---|
| `U` | `UObject` 派生 | `CoreUObject`、`Engine` |
| `A` | `AActor` 派生 | `Engine` |
| `F` | 普通类 / 结构体 | `Core`、`CoreUObject` |
| `I` | 接口 | 按语义猜模块 |
| `T` | 模板 | `Core` |
| `E` | 枚举 | 按语义猜模块 |

再在候选路径里精确搜索。**不要带导出宏，也不要加行首锚点**——实测这两类写法都会 0 命中，
白白浪费几轮：

| 失败写法 | 为什么失败 |
|---|---|
| `^class COREUOBJECT_API UObject` | `UObject` 用的是 `UCLASS(..., MinimalAPI, ...)`，类名前**没有**导出宏 |
| `class CORE_API FName` | `FName` 是成员级导出，类名就是裸的 `class FName` |

正确的搜索阶梯，从宽到窄逐个试：

| 顺序 | 模式 | 适用形态 |
|---|---|---|
| 1 | `^\s*(class|struct)\s+\w*_?API\s+<类型名>\b` | 类级导出宏 |
| 2 | `^\s*(class|struct)\s+<类型名>\b` | 无导出宏、顶格声明 |
| 3 | `UCLASS\(.*\)[\s\S]{0,80}class\s+<类型名>\b` | 反射类，`UCLASS` 在类名上一行 |
| 4 | `\b(class\|struct)\s+<类型名>\b` | 兜底，允许不顶格 |

**检查点**：命中必须带**类体**（后面跟 `{=` 或继承冒号），而非前置声明（`class FName;` 后就分号）。
只有前置声明时换下一级模式重试。**不要拿前置声明当定义写文档。**

0 命中时的排查顺序：

1. 换更宽的搜索模式（第 3、4 级）
2. 换模块——类型不一定在你猜的模块里
3. 去掉 `glob` 限制，扩大搜索根
4. 仍无命中 → 按"类型不存在"处理（见输出示例 3）

**不要在搜索失败时凭记忆写出文件路径。** 多花一次目录列举的成本，
远低于产出一篇引用不存在文件的文档。

### Step 2: 读声明，确认四件事

读头文件中该类型的声明区：

1. **导出策略** —— **不要假设存在类级导出宏。** 实测四种形态都存在，必须按原文件判定属于哪一种：

| 形态 | 长相 | 例子 |
|---|---|---|
| 类级宏 | `class IRISCORE_API UNetRefHandleGenerator : public UObject` | 类名前直接带 `*_API`（`NetRefHandleGenerator.h` 第 28 行） |
| `MinimalAPI` | `UCLASS(..., MinimalAPI)` + `class AActor : public UObject` | 类名前**无**宏，只导出 `StaticClass()`；成员逐个标注 `*_API`（`Actor.h` 第 281/282/288 行） |
| 逐成员宏 | `class FName` + 成员前 `CORE_API` | 类名前**没有**任何宏 |
| 逐成员宏 + 编译期开关 | 同一成员在 `#if` 分支里是 `CORE_API` 外链、`#else` 里是 `FORCEINLINE` | `FName` 的 `GetComparisonIndex` 受 `UE_FNAME_OUTLINE_NUMBER` 控制 |

写产物时不要只写"有/无导出宏"，要写清**导出粒度**（类级 / 仅 `StaticClass` / 成员级）。
按"通常有类级宏"的直觉推断，会产出与实际不符的声明描述——这是本技能最容易出错的一项。
2. **反射宏** —— `UCLASS` / `USTRUCT` / `UENUM` / `UINTERFACE`，以及紧随其后的 `GENERATED_BODY()` 或 `GENERATED_UCLASS_BODY()`
3. **基类** —— 完整继承链，逐级追溯到 `UObject` 或链条尽头
4. **命名空间** —— 是否在全局命名空间；不在时写全限定名

### Step 3: 提取公开 API 与扩展点

| 要提取的 | 在哪看 |
|---|---|
| 公开成员函数 | `public:` 段 |
| 可见属性 | `UPROPERTY` 标注的成员 |
| 蓝图可调用函数 | `UFUNCTION(BlueprintCallable)` 等标注 |
| **扩展点** | `virtual` 函数，尤其是标记为可覆写的 |
| 生命周期钩子 | 如 `BeginPlay` / `EndPlay` / `Tick` 之类，**只写何时被调用，不写谁调用** |
| 内部实现 | `protected:` / `private:` 段，只做概要，不逐个列 |

**检查点**：扩展点表必须区分「可覆写的虚函数」与「仅供内部调用的虚函数」。
把内部虚函数列成扩展点，会误导程序员去覆写不该覆写的东西。

### Step 4: 反向找派生类（限定范围）

只在**纳入范围的模块**内搜索派生类：

```
search_content: pattern="\bpublic\s+<基类名>\b" glob="*.h"
```

**检查点**：产物中必须写明搜索边界，例如：
"派生类搜索仅覆盖本版纳入范围的 292 个模块，引擎其余部分（Editor / Developer / Platforms / 未纳入的 Plugins）未覆盖。"
**不写边界的派生类列表会被读成"全部派生类"**，这是错误信息。

### Step 5: 写产物

路径：`docs/types/<类型名>.md`，类型名保持英文原名（含前缀，如 `AActor.md`）。

## 输出示例

**示例 1：正常路径**

输入：`分析一下 UE 的 AActor 类`

应做：按 `A` 前缀定位到 `Engine` 模块 → 搜到 `Actor.h` → 读声明
（`UCLASS(..., MinimalAPI)`、类声明行**无**导出宏、基类 `UObject`）→ 提取公开 API 与虚函数
→ 在范围内搜派生类 → 写 `docs/types/AActor.md`。

**示例 2：结构体而非 UCLASS 类（边界）**

输入：`FName 是怎么定义的`

应做：确认 `FName` 是 `Core` 模块下的结构体，**没有 `UCLASS`**（它是非反射的轻量类型）。
产物「反射宏」一行写"无"，并说明它是非 `UObject` 体系的值类型。

不应做：因为没有 `UCLASS` 就判定"这不是一个类型"而拒绝分析。

**示例 3：类型不存在（异常）**

输入：`分析一下 UAwesomeThing 类`

应做：在候选模块内搜索无命中 → 再用不限定模块的全库搜索确认一次 → 告知用户本引擎里没有该类型，
提示是否拼错或是否是项目自己的类（引擎源码里当然找不到）。

不应做：找相近名字的类然后"当作"用户要的类来分析。

**示例 4：接口（边界）**

输入：`分析一下 IModuleInterface`

应做：注意到它是接口，反射宏为 `UINTERFACE`（若适用），并说明其用途是模块生命周期。
若接口无反射宏（纯 C++ 接口），如实写明。

## 常见问题

### Q: `UE_5.x` 里同一个类名出现多次怎么办？

可能是不同模块的同名类，也可能是类的前置声明 + 定义。
按"有 `UCLASS`/`USTRUCT` 且有大括号体"判定真正的定义；仍有多个时，把候选路径列给用户选。

### Q: 头文件在 `Public/` 还是 `Private/` 有区别吗？

有，且必须写进产物。`Public/` 下的类型是模块对外契约，`Private/` 下的是实现细节，
消费者不应该直接依赖后者。把 `Private/` 类型写成公开 API 是错误。

### Q: 要不要展开模板（`TArray`、`TMap`）的完整 API？

模板类型 API 量极大，且大量是特化实现。做法：只列**常用 API 与关键行为约定**
（如 `TArray` 的内存布局、扩容策略、与 `TMap` 的哈希依赖），
并标注"完整 API 见头文件"。逐条罗列模板全部重载没有可读性。

### Q: 派生类搜索范围为什么不能全库？

会命中 Editor / Developer / 大量 Plugins 下的类，既拖慢又污染结论（使用者多半不关心编辑器侧派生类）。
限定范围 + 明写边界，比全库但语义含糊更有价值。
