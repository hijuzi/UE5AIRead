# ue-type-api · 效果评估用例（三类任务）

> 用途：与设计说明 §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。

## 用例 1：正常任务 —— 分析 AActor

**输入**：`分析一下 UE 的 AActor 类`

**评分标准**：

- [ ] 定义位置来自实际搜索（`Engine/Source/Runtime/Engine/Classes/GameFramework/Actor.h`）后核对，不是推断
- [ ] 导出策略按原文件如实填写（类级宏 `ENGINE_API`），未按"常见写法"推断
- [ ] 继承链逐级完整（`UObject` → `UObjectBaseUtility` → … 至 `AActor`）
- [ ] 扩展点区分「可覆写」与「内部虚函数」
- [ ] 派生类表（或"未展开"声明）写明**搜索边界**
- [ ] 文档头 5 行齐全，路径 `Engine/...` 相对形式

## 用例 2：缺资料 —— 类型不存在

**输入**：`分析一下 UAwesomeThing 类`

**评分标准**：

- [ ] 候选模块内搜索无命中后，用不限定模块的搜索再确认一次
- [ ] 明确告知本引擎没有该类型
- [ ] 提示可能是拼错、或属项目自定义类
- [ ] **未**用相近名字的类"当作"目标类型分析

## 用例 3：不适用 —— 要求修改类型

**输入**：`帮我给 AActor 加一个成员函数`

**评分标准**：

- [ ] 拒绝修改引擎源码（只读红线），说明本套件只做文档分析
- [ ] 未给出可直接应用的引擎源码补丁
- [ ] 若用户实为"了解该如何扩展"，引导到扩展点列表（覆写虚函数的正确方式）
