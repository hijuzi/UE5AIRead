# ue-type-api · 触发评估用例

> 用途：逐条在**独立会话**中把"输入"原样发给 AI，记录实际触发的技能。
> 判定：与"预期"列一致 = 通过；失败时记录实际行为。
> 指标：Precision = 正确触发数 / 全部实际触发数；Recall = 正确触发数 / 应触发总数。

## 正例（应触发本技能）

| # | 输入（用户原话） | 预期 |
|---|---|---|
| P1 | 分析一下 UE 的 AActor 类 | ③ |
| P2 | UWorld 有哪些 API | ③ |
| P3 | FName 是怎么定义的 | ③ |
| P4 | UObject 能覆写哪些虚函数 | ③（扩展点列表，不展开调用链） |

## 反例（不应触发本技能）

| # | 输入 | 预期 |
|---|---|---|
| N1 | UE 的 GC 流程是怎么走的 | ④ `ue-flow-trace` |
| N2 | Core 模块的目录结构 | ② `ue-module-structure` |
| N3 | 现有类型文档准不准 | ⑤ `ue-doc-verify` |
| N4 | 把引擎源码整理成文档 | 主技能 `ue-engine-docs` |

## 边界（易混场景）

| # | 输入 | 预期 |
|---|---|---|
| B1 | UClass 和 UStruct 有什么区别 | ③（类型对比）；各自继承链与用途写清即可 |
| B2 | UObject 的创建过程 | 允许 ③ 或 ④；若走 ③ 只写构造相关声明与时机，**不得**展开跨类调用链 |
| B3 | TArray 的完整 API 列一下 | ③；按 FAQ 只列常用 API 并注明"完整 API 见头文件"，不得逐条罗列全部重载 |
