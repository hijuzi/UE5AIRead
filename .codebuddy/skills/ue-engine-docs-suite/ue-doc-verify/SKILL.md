# UE5 文档库事实校验

对 `docs/` 下的既有产物做**独立回查**，产出 `docs/_meta/quality-report.md`，并回填校验状态。

本技能是保障类技能：**只做验证与修正，不新增事实内容**。
它的价值在于"换一个人、换一条路径重新取一次数"——生产技能自证不算校验。

## ⛔ 执行前置：先确认证据源完整

回查"零命中 / 不存在 / 不可判定"类结论时，**证据源本身的完整性决定结论对错**。
开工前先跑：

```powershell
.codebuddy\skills\ue-engine-docs-suite\ue-engine-docs\scripts\check-source.ps1 -SourceRoot "<引擎源码根>"
```

| `Verdict` | 对校验的影响 |
|---|---|
| `Complete` | 声明层与实现层引用都可核对 |
| `HeadersOnly` | **实现层引用（`.cpp` 行号）全部记"未判定"**，不得判为"不存在"（历史教训：曾把"仅头文件安装看不见"误判成"不存在"并写进产物） |

## 职责边界

| 本技能负责 | 本技能**不做** |
|---|---|
| 回查引用：文件是否存在、行号区间内容是否与说明相符 | 新增段落、补写缺失内容（→ 对应生产技能） |
| 路径规范、文档头、版本锚点合规性 | 重新生成整篇文档 |
| 交叉链接与 `00-索引.md` 一致性 | 跨版本差异比较（→ `ue-doc-sync`，本版未启用） |
| 引擎版本实读核对（`Build.version`） | 性能 / 正确性评审（只查"写的是否属实"） |
| 修正事实错误 + 回填 `校验状态` | 修改规范本身（改动 `convention.md` 需明确理由并留变更记录） |

**判断标准**：本条发现的问题，能不能用"文件 + 行号"证明产物写错了？
能证明 → 修正；不能证明 → 记「未判定」，**不要用推测替换**。

## 核心约束

1. **先机器初筛，再人工抽样。** 不要一上来逐字读产物——`verify-refs.ps1` 先筛
   "文件不存在 / 行号越界 / 文档头缺失 / 路径违规"四类硬错误（零成本、全量），
   人工只做机器做不了的**语义核对**（行号区间内容是否符合该行说明）。
2. **抽样必须分层，否定结论必须全查。** 分层见 Step 3；
   **所有"不存在 / 未找到 / 不可判定 / 未覆盖"类结论 100% 复核**——这类结论最容易被"证据源残缺"污染。
3. **修正只改 `docs/`。** 行号错、路径错、链接错 → 直接修正；
   缺失内容 → 记「建议」交回生产技能，**不擅自扩写**。
   实质修正须在该产物末尾追加「更新记录」（`convention.md` 第八节），只刷新不改事实的更新刷新「生成时间」。
4. **回填规则**：该篇"必查项全部通过或已修正"才能回填 `已校验（YYYY-MM-DD）`；
   存在未判定项时，回填 `已校验（YYYY-MM-DD，含 N 项未判定）`，N 与报告一致。
   已回填的产物若再次被实质修改，**状态重置为 `未校验`**，由本技能重跑。
5. **只读引擎**：本技能全程不写引擎任何文件；引擎侧只核对**版本号**（见 Step 4），
   **不用 mtime**——文件时间戳会因重装 / 整目录复制整体漂移，不构成"是否被误改"的证据。

## 执行步骤

### Step 0: 前置检查

1. `docs/_meta/convention.md` 存在（版本锚点真源）。
2. `docs/` 下至少有 1 篇产物（`modules/` `types/` `flows/` 任一）。
3. 跑 `check-source.ps1`，记录 `Verdict` 与 `.cpp` 数。

> **产物为 0 时的处置（硬规则）**：**停下，不产出任何报告**——明确告知"无产物可校验"，
> 提示先跑生产技能（②③④）产出内容，然后结束。
> **不得**产出空的或编造的 `quality-report.md`：空报告会被下游当成"校验通过"。
> 与"产物少"的区别：**≥ 1 篇**属"样本量小"，照常执行（见示例 4）；**0 篇**才适用本条。

> 产物数量提示：技能可随时运行；**≥ 10 篇时边际价值最大**（批量回查摊薄固定成本）。

### Step 1: 收集校验目标

列出 `docs/modules/`、`docs/types/`、`docs/flows/` 下全部 `.md`，从每篇文档头读
「生成技能 / 生成时间 / 校验状态」。输出待校验清单。同时读 `00-索引.md` 的产物表备用（Step 4 一致性用）。

### Step 2: 机器初筛（全量）

```powershell
.codebuddy\skills\ue-engine-docs-suite\ue-doc-verify\scripts\verify-refs.ps1 -DocsRoot "docs" -EngineRoot "E:\EpicGames\UE_5.8"
```

脚本输出八组检查（全部可机器判定）：

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 引用文件存在性 | 所有 `Engine/...` 引用路径在安装根下存在 |
| 2 | 行号越界 + 覆盖率 | 所有**可绑定**的行号引用满足 `B ≤ 文件总行数`。可绑定 = `convention.md` 4.3 承认的三种合法形式（块式 / 名在前 / 数字在前且文件名**紧邻**）；写成「（第 N 行）」这类"文件名在别处"的形式会被计为 **unbound**——如实报数，**不猜、也不报错**（启发式绑定会造假 FAIL，实测已证） |
| 3 | 文档头 | 前 6 行含 5 个字段（引擎版本 / 源码根 / 生成技能 / 生成时间 / 校验状态） |
| 4 | 路径违规 | 产物正文无盘符、无反斜杠形式的引擎路径、无"相对 `Engine/`"写法 |
| 5 | 引擎版本锚点 | 实读 `Engine/Build/Build.version`，输出 `UE x.y.z (Build N)`，供 Step 4 判读 |
| 6 | **计数断言复算**（`convention.md` 4.2.1） | `[M]` 行按**白名单**命令形态（`Get-ChildItem` / `ReadAllLines` / `Select-String` 含 `-Range A-B`），用校验过的参数**重新构造并实际执行**，结果须与断言数字一致 |
| 6b | **计数断言覆盖**（FAIL 级） | 正文的计数断言（`N 处 / N 个 / N 条 / N 项 / N 文件 / N 头文件 / N 命中`，已排除代码块与表格行）须在「取数说明」节有对应数字；缺失即 FAIL |
| 6c | **方法标记声明**（FAIL 级） | 每行须以 `[M]` / `[R]` / `[H]` 开头：`[M]` 行必须能真跑出结果，`[R]` 行来源须存在，`[H]` 行引用的引擎文件须存在；**未声明即 FAIL** |

> **[6c] 是"不可复算"的收口**：大量计数天然只能人工通读（"类内 is 段 12 条"），
> 若放任它们静默跳过，检查器只报"跳过 N 行"而无法判断该不该跳。
> 因此规范要求每行**显式声明方法类别**——把"不可复算"从默认状态变成需要声明的例外。

**检查点**：硬错误清单清零（修正后重跑脚本，直到为空）。无法清零的转入「未判定」并说明原因。

### Step 3: 分层抽样语义核对（人工）

对每篇产物按下列分层抽样，核对"行区间内容与该行说明是否相符"：

| 层 | 内容 | 最低抽样 |
|---|---|---|
| A | 定义 / 声明位置类引用 | 每篇 ≥ 3 处 |
| B | 行号区间类引用（`行 A-B`） | 每篇 ≥ 3 处 |
| C | 跨模块 / 跨文件类引用 | 每篇 ≥ 2 处 |
| D | 宏 / 模板 / 条件编译类引用 | 每篇 ≥ 2 处 |
| E | **否定类结论**（不存在/未找到/不可判定/未覆盖） | **100%** |

总量规则：可解析引用点 < 30 的产物抽 ≥ 10 处；≥ 30 的抽 ≥ 30%。用户可要求全量。

核对动作：`read_file` 打开引用位置 → 比对内容 → 记录结论（通过 / 修正 / 未判定）。

**检查点**：每条被抽中的引用必须落下三态之一，不允许"看起来差不多"（"差不多" = 未判定）。

### Step 4: 专项复核（每轮必做）

| # | 专项 | 方法 |
|---|---|---|
| 1 | 版本锚点 | 每篇文档头的引擎版本 = `convention.md` 本机环境块；生成技能版本 = 该技能 `metadata.version` |
| 2 | 索引一致性 | `00-索引.md` 产物表 ↔ 实际文件（多 / 少 / 校验状态列） |
| 3 | 交叉链接 | 每篇「相关文档」列的路径全部存在 |
| 4 | 引擎版本实读 | 用 Step 2 输出的版本号，核对 `convention.md` 本机环境块与全部产物文档头三者一致（不一致即停止校验并报告） |
| 5 | 零命中结论 | 对照 `check-source.ps1` 的 `Verdict` 复核全部否定类结论（与 Step 3-E 合并执行） |

### Step 5: 写报告

路径：`docs/_meta/quality-report.md`。

````markdown
> 报告日期：YYYY-MM-DD
> 校验技能：ue-doc-verify v1.0
> 引擎版本：<复制自 convention.md>
> 源码形态：<Complete / HeadersOnly>（check-source.ps1 实测）

# 文档库校验报告

## 一、校验范围与方法

| 项 | 值 |
|---|---|
| 校验产物 | N 篇（列出） |
| 机器初筛 | verify-refs.ps1：文件存在性 / 行号越界 / 文档头 / 路径 / 引擎版本锚点 |
| 语义抽样 | 分层 A–E，抽 X/Y 处（E 层全查） |
| 未覆盖 | 本次未做的检查项及原因 |

## 二、结果总表

| 产物 | 引用点 | 抽检 | 通过 | 修正 | 未判定 | 校验状态 |
|---|---|---|---|---|---|---|

## 三、修正清单

| # | 产物 | 位置 | 原文 | 实际 | 处置 |
|---|---|---|---|---|---|

（无修正时写"无"）

## 四、未判定项

| # | 产物 | 内容 | 原因 |
|---|---|---|---|

（无时写"无"）

与 `00-索引.md` 的覆盖度一致；如不一致，说明差异来源。

## 六、引擎版本核对

实读版本号（`Engine/Build/Build.version`）、与文档头的比对结果、结论（一致 / 不一致）。

## 七、遗留与建议

- 下一次校验建议的触发条件
````

### Step 6: 修正与回填

1. 按修正清单修改产物（含末尾「更新记录」）。
2. 修完后**重跑 Step 2 脚本**确认硬错误清零。
3. 回填校验状态：产物文档头 + `00-索引.md` 校验状态列（索引中仅此列由本技能回填）。

### Step 7: 交回主技能

告知用户：校验篇数、修正条数、未判定条数、引擎版本核对结论。
由主技能在 `docs/设计说明-UE5引擎文档技能套件.md` 记录本轮校验。

## 输出示例

**示例 1：正常路径**

输入：`校验一下现有文档`
应做：Step 0 确认 `Complete` → Step 1 列 5 篇 → Step 2 脚本 0 硬错误 →
Step 3 分层抽样 40 处全通过 → Step 4 专项全过 → 报告"无修正" →
回填 5 篇为 `已校验（日期）` → 交回。

**示例 2：发现错误（边界）**

输入：同上，抽样发现 `types/UObject.md` 某行号偏移 3 行。
应做：修正行号 → 该篇末尾追加「更新记录」→ 重跑脚本 → 回填 →
报告修正清单 1 条。不应做：顺手"优化"该篇其他段落（那是生产技能的职责）。

**示例 3：证据源受限（异常）**

输入：同上，但 `check-source.ps1` 报 `HeadersOnly`。
应做：实现层引用（`.cpp` 行号）全部记「未判定」并在报告第四节列出；
回填为 `已校验（日期，含 N 项未判定）`；禁止把实现层引用判为"不存在"。

**示例 4：产物太少（边界）**

输入：`只有 2 篇产物，校验一下`
应做：照常执行并产出报告，在报告"校验范围"注明"样本量小，覆盖度低"。
不应做：以"篇数不足"为由拒绝执行（阈值是价值判断，不是执行门槛）。
（**注意**：本条只适用于 `docs/` **至少有 1 篇产物**的情形；0 篇时按 Step 0 的硬规则停下，不产出报告。）

## 常见问题

### Q: 抽样多少才够？

分层下限（Step 3 表）是底线不是目标；引用密度高的产物（如 flows/）多加。
**没有"抽多少都行"的余地**：每篇的 A–D 层至少要抽到各层下限，E 层不允许抽样。

### Q: 发现内容错误，但不知道正确内容是什么？

记「未判定」并写清"为什么无法判定"（如需要实现体、需要跨平台环境）。
**不要为了消灭未判定项而猜一个答案**——未判定是合法结论，猜错不是。

### Q: 校验发现产物漏写了重要内容，能顺手补吗？

不能。记入报告第七节「遗留与建议」，交回对应生产技能执行。
本技能新增的任何"事实"都绕过了生产技能的引用纪律，是校验体系的漏洞。

### Q: 生产技能刚产出 1 篇就要求校验，值得吗？

值得，但要在报告中注明"样本量小"。校验的价值随篇数增长：单篇校验 ≈ code review，
批量校验才能发现系统性偏差（如某个生产技能的行号偏置、模板字段缺失）。
