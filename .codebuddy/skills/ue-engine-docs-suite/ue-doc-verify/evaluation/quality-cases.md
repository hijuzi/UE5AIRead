# ue-doc-verify · 效果评估用例（三类任务）

> 用途：与 `docs/设计说明-UE5引擎文档技能套件.md` §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。
> 判定：逐条落"结论"列——全项勾选 = `通过`；有未勾选项 = `失败`（备注写明未勾哪几项）。
> 重跑时机：本技能步骤 / 示例变更后重跑本文件；`description` 变更后重跑 `trigger-cases.md`（见 `使用说明.md` 第八节）。

## 用例 1：正常任务 —— 全量校验

**输入**：`校验一下现有文档`

**评分标准**：

- [ ] 先跑 `check-source.ps1` 记录 `Verdict`（源码形态前置）
- [ ] 跑 `verify-refs.ps1` 机器初筛，硬错误清零后才进入人工层
- [ ] 分层抽样覆盖 A–D 层，**否定类结论 100% 复查**
- [ ] 每个抽中引用落下"通过 / 修正 / 未判定"三态之一
- [ ] `quality-report.md` 七节齐全；修正清单与实际修正一致
- [ ] 实质修正的产物末尾追加「更新记录」
- [ ] 校验状态回填（产物头 + `00-索引.md`），数值与报告一致

## 用例 2：缺资料 —— 无产物可校验

**输入**：`校验一下 docs 里的文档`（`modules/` `types/` `flows/` 均为空）

**评分标准**：

- [ ] 明确告知无产物可校验（"无产物时无意义"）
- [ ] **未**产出空的或编造的 `quality-report.md`
- [ ] 提示先跑生产技能（②③④）产出内容

## 用例 3：不适用 —— 要求重写文档

**输入**：`把质量报告里提到的问题文档重写一遍`

**评分标准**：

- [ ] ⑤ 明确不做"新增 / 重写内容"（只校验与修正事实错误）
- [ ] 将"重写"需求交回对应生产技能，或对"事实错误"部分直接修正并留痕
- [ ] 未借"重写"名义新增未经引擎源码核实的内容
