# ue-doc-verify · 触发评估用例

> 用途：逐条在**独立会话**中把"输入"原样发给 AI，记录实际触发的技能。
> 判定：与"预期"列一致 = 通过；失败时记录实际行为。
> 指标：Precision = 正确触发数 / 全部实际触发数；Recall = 正确触发数 / 应触发总数。

## 正例（应触发本技能）

| # | 输入（用户原话） | 预期 |
|---|---|---|
| P1 | 校验一下现有文档 | ⑤（先跑 `check-source.ps1` 前置） |
| P2 | 核对文档里的行号引用 | ⑤ |
| P3 | 文档和源码对不上吗 | ⑤ |
| P4 | 出一份文档质量报告 | ⑤（产出 `_meta/quality-report.md`） |

## 反例（不应触发本技能）

| # | 输入 | 预期 |
|---|---|---|
| N1 | 写一篇 Engine 模块的结构文档 | ② `ue-module-structure` |
| N2 | 分析一下 UObject 的 API | ③ `ue-type-api` |
| N3 | 生成 AI 检索索引 | ⑥ `ue-ai-index` |
| N4 | 把 UE 源码整理成文档 | 主技能 `ue-engine-docs` |

## 边界（易混场景）

| # | 输入 | 预期 |
|---|---|---|
| B1 | 检查一下 docs 有没有错误 | ⑤（"检查+文档"落入校验语义） |
| B2 | Core 模块的文档要不要更新 | 允许 ⑤（先校验出结论）或主技能；**不得**直接变成 ② 重写文档 |
| B3 | docs 目录下现在有几篇产物 | 信息查询，无需加载任何技能；若加载，⑤ 不应启动全量校验 |
