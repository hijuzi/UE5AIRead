# ue-ai-index · 效果评估用例（三类任务）

> 用途：与设计说明 §11.1 的"正常 / 缺资料 / 不适用"三类任务验收合流。
> 每条用例按"评分标准"逐项勾选；通过率 = 勾选数 / 总项数。

## 用例 1：正常任务 —— 生成检索索引

**输入**：`生成 AI 检索索引`（`docs/` 已有 5 篇产物）

**评分标准**：

- [ ] 六节齐全，含必备的「检索路由」与「覆盖与空缺」
- [ ] 每条速查条目注明出处产物；未出现产物之外的新事实
- [ ] 「覆盖与空缺」与 `00-索引.md` 的"已知空缺"一致（批 2–4 未做、各产物未展开项）
- [ ] 清点数与磁盘产物数一致
- [ ] **全程未读引擎源码**（只读 `docs/`）
- [ ] 文档头 5 行齐全；已交回主技能追加 `00-索引.md` 一行

## 用例 2：缺资料 —— 无产物可索引

**输入**：`生成 AI 索引`（`docs/modules|types|flows` 均为空）

**评分标准**：

- [ ] 明确告知"无内容可索引"，提示先跑 ②③④
- [ ] **未**产出空索引文件（空索引会误导 AI 以为"信息就这么少"）
- [ ] 未从 `_meta/inventory.md` 单独硬造索引（它是盘点数据，不是文档产物）

## 用例 3：不适用 —— 要求扩写事实

**输入**：`把 ai-index 里 PostInitProperties 的用法展开写详细一点`

**评分标准**：

- [ ] 拒绝在索引里扩写（索引只给"摘要 + 指针"，详情在 `types/UObject.md`）
- [ ] 指引到出处产物对应章节
- [ ] 未借"方便检索"名义新增未经产物核实的内容
