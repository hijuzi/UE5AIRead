# UE5 引擎文档技能套件 · 使用说明

> 一句话：把 UE5 引擎源码变成**可核验的技术文档库**（给程序员读 + 给 AI 检索）。
> 当前可用技能：**7 个**（另有 ⑦ 未启用，见第三节）。
> 适用环境：Windows；引擎锁定本机 `UE 5.8.3`（真实路径以 `docs/_meta/convention.md` 的「本机环境」块为唯一真源）。

---

## 一、这套技能产出什么

所有产物都落在仓库根 **`docs/`**（唯一写入边界；引擎源码全程只读）：

| 想了解 | 看哪里 | 由谁产出 |
|---|---|---|
| 某个**模块**的结构与依赖 | `docs/modules/<模块>-结构.md` | ② `ue-module-structure` |
| 某个**类**的继承链与 API | `docs/types/<类名>.md` | ③ `ue-type-api` |
| 某个**机制**的调用链与时序 | `docs/flows/<机制名>.md` | ④ `ue-flow-trace` |
| 引擎有哪些模块、规模多大 | `docs/_meta/inventory.md` | ① `ue-engine-inventory` |
| 文档准不准（校验报告） | `docs/_meta/quality-report.md` | ⑤ `ue-doc-verify` |
| AI 该去哪里找答案（检索路由） | `docs/ai/ai-index.md` | ⑥ `ue-ai-index` |
| 全部产物的总入口 | `docs/00-索引.md` | ★ `ue-engine-docs`（主技能） |

每篇产物头部都带**版本锚点**（引擎版本 + 生成技能 + 校验状态）——升版后能判断文档是否仍有效。

## 二、快速开始（三种典型用法）

1. **从零整理一整套**：说 `把 UE5 引擎源码整理成技术文档`
   → 主技能接管：先盘点拿到批次表 → 你确认后逐批推进（不会直接开读源码）。
2. **查一个具体对象**：
   - `分析一下 UE 的 Core 模块` → ②
   - `AActor 是怎么定义的` → ③
   - `UObject 的创建流程是怎么走的` → ④
3. **校验已有文档**：说 `校验一下现有文档` → ⑤（先确认源码形态，再机器初筛 + 人工抽样回查行号）。

## 三、技能清单

| # | 技能 | 干什么 | 典型触发说法 | 产物 |
|---|---|---|---|---|
| ★ | `ue-engine-docs` | 总编排：初始化文档库、路由任务、维护索引 | "把源码整理成文档""建知识库"（意图笼统时） | `docs/00-索引.md` |
| ① | `ue-engine-inventory` | 盘点模块清单与规模、定批次 | "有哪些模块""先做哪几个" | `_meta/inventory.md` |
| ② | `ue-module-structure` | 模块目录、`Build.cs` 依赖、暴露面、模块入口 | "分析 Core 模块""依赖哪些模块" | `modules/<模块>-结构.md` |
| ③ | `ue-type-api` | 继承链、反射宏、导出策略、公开 API、扩展点 | "AActor 的继承链""UObject 有哪些 API" | `types/<类名>.md` |
| ④ | `ue-flow-trace` | 入口点、逐层调用链、数据流、未覆盖分支 | "GC 流程怎么走的""谁调用 BeginPlay" | `flows/<机制名>.md` |
| ⑤ | `ue-doc-verify` | 回查引用的文件与行号、校验状态回填 | "校验文档""核对行号""出质量报告" | `_meta/quality-report.md` |
| ⑥ | `ue-ai-index` | 把已有产物重组为 AI 检索路由与锚点速查 | "生成 AI 检索索引""给文档做个检索入口" | `ai/ai-index.md` |
| ⑦ | `ue-doc-sync` | 升版增量维护（**占位，未启用**） | — | — |

**触发要领**：说出**对象粒度**（模块名 / 类名 / 机制名）就会路由到对应技能；
意图说不清时主技能兜底，它会先反问你或给出批次表。

## 四、完整流水线

```
① 盘点（已有 inventory，通常不用重跑）
      ↓
② 模块文档  ──→ ③ 类型文档（0..N 篇）──→ ④ 流程文档（0..M 篇）
      ↓                                            ↓
      └────────────→ ⑤ 校验（攒几篇后跑一次）←────┘
                          ↓
                    ⑥ 索引（产物 ≥10 篇后重跑，供 AI 检索）
```

- 顺序有依赖：② 的"暴露面清单"帮 ③ 定位类型；③ 的类型文档被 ④ 交叉引用；
  ⑤ 最后跑，回填每篇的校验状态。**跳过 ②③ 直接写 ④ 会产出指向不存在文档的链接。**
- 并非每个对象都要跑全链：小模块可能没有值得单独成篇的流程（④ 可省）。
- 单点使用也合法：每一步都能独立触发（例如只要求"分析一下 EnhancedInput 模块"）。

## 六、前置条件与硬约束

| 项 | 说明 |
|---|---|
| 操作系统 | Windows（脚本为 PowerShell） |
| 引擎 | 本机 `UE 5.8.3 (Build 58210709)`；路径见 `docs/_meta/convention.md` |
| 源码形态 | 开工前由 ★ 或 ④ 跑 `check-source.ps1` 确认；`HeadersOnly` 时 ④ 不可执行 |
| **引擎源码只读** | 全部技能禁止对引擎安装根写文件；写入仅限 `docs/` |
| 路径写法 | 文档内一律 `Engine/...` 相对形式，不带盘符、用正斜杠 |
| 校验状态 | 产物头 `未校验` → ⑤ 通过后回填 `已校验（YYYY-MM-DD）` |

## 七、常见问题

**Q: 我说的话会触发哪个技能？**
看对象粒度：模块名 → ②；类名（`U`/`A`/`F`/`I` 前缀）→ ③；"流程/调用链/怎么走的" → ④；
"校验/核对/准不准" → ⑤；"索引/检索入口/让 AI 更好找" → ⑥；
只有"整理/建库/怎么组织"之类笼统词 → ★ 主技能兜底。

**Q: 技能没有被触发 / 移动目录后行为异常？**
技能清单由宿主在**会话启动时**扫描。本次套件目录收拢（2026-10-10）之后，
**新开会话**即从新路径加载；已打开的旧会话不受影响，重启 IDE 可确保刷新。

**Q: 发现文档写错了怎么办？**
直接说 `校验一下现有文档`——⑤ 会机器初筛 + 抽样回查，事实错误当场修正并把修正记入产物末尾「更新记录」。
想单独核一篇也行：`核对一下 flows/UObject创建流程.md 的行号`。

**Q: 想给一个新模块出文档？**
先让 ★/① 确认该模块在 `engine-modules.json` 里存在（名字像但不在的模块会查无此表），
再依次跑 ② → ③（需要时 ④）。不在首批白名单的模块需要先讨论是否扩面。

**Q: 引擎升级到新版本了怎么办？**
⑦ `ue-doc-sync` 尚未启用。先按 `docs/_meta/convention.md` 的版本锚点定位受影响产物：
文档头的引擎版本与新版不符的，都需要重新校验或重做；跨大版本变化请先人工评估再动。

**Q: `evaluation/` 目录是什么？**
每个技能的**评估用例**：`trigger-cases.md`（触发准确性：正例/反例/边界）+
`quality-cases.md`（效果：正常/缺资料/不适用三类任务 + 评分标准）。
用于技能改版后的回归测试——改完 SKILL.md 后可逐条在独立会话中验证。

**Q: `ai/ai-index.md` 和 `00-索引.md` 有什么区别？**
`00-索引.md` 是**给人看的目录**（库里有什么文件、校验状态），由 ★ 主技能维护；
`ai/ai-index.md` 是**给 AI 用的检索路由**（查 X 去哪篇哪节 + 锚点速查 + 覆盖边界），由 ⑥ 维护。
两者互补：人看目录选文件，AI 看路由直达章节。产物 ≥10 篇后应重跑 ⑥ 刷新路由。

**Q: 在哪里看这套技能的设计与进度？**
- `docs/设计说明-UE5引擎文档技能套件.md` —— 设计原理、批次、每次实跑/评估的记录（**最全的单一入口**）
- `docs/_meta/skill-suite-assessment.md` —— 技能套装第三方评估报告
- `docs/_meta/quality-report.md` —— 最新一次文档校验结果

## 八、给维护者

1. **改技能后跑回归**：改 `SKILL.md` 的 description → 重跑该技能的 `evaluation/trigger-cases.md`；改步骤/示例 → 重跑 `quality-cases.md`。
2. **修正可检索事实（版本号/行数/路径）后**：按主技能 Step 5 反向全库检索旧值，确认无残留。
3. **数字类断言**：注明取数命令或实测时点，不要凭目视估算。
4. **新增技能**：先读设计说明第 3 节的"独立成技能三问"，并保持 description 与既有技能的差异化。
