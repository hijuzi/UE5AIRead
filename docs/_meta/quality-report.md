   而**行号类断言准确率极高**（约 1,800 处行号引用仅 9 处错）。
2. **跨模块否定式断言最危险**：`Renderer` 的"首个覆写者、其余均未覆写"与 `UMG` 的"无 `Tests/`"，
   都是用**一个模块的观察去断言全库**，且**机器初筛完全查不出来**。
3. **"行号对但文件指错"是一种隐蔽失效**：`Sockets` 把 `.cpp` 的行号记成"头文件第 N 行"——
   读者按索引会打开错误文件，而越界检查照样通过。

## 十三、2026-10-15 行号引用覆盖率复算与写法收紧

> 触发：复核「约 1,800 处行号引用只错 9 处」这句话时，怀疑 `convention.md`、`00-索引.md`
> 与脚本输出三处数字互相矛盾。复算后确认**不是矛盾，是三个口径**——但也因此发现
> 机器覆盖率只有 **9.9%**。

### 13.1 复算结论：三个口径，不是三个矛盾值

| 口径 | 值 | 说明 |
|---|---|---|
| **语义核对点** | **≈1,860**（每篇约 27） | 第九节的抽样核对项总数（跨全部断言类型；行号类是其中一个子集，约 1,800） |
| **行号引用总数** | **2,058** | 全库正文中的行号指向：`行 N` **302** + `第 N 行` **1,756** |
| **机器可绑定** | **204 → 514** | 脚本能绑定到文件并校验越界的部分 |

**措辞更正**：`convention.md` 4.2 正文原写"约 1,800 处**行号引用**"，实为**核对点**——
把"人工抽样的核对项"误述成了"行号引用"。已在 v1.6 更正，并新增 4.4 口径表。

### 13.2 真正的发现：机器覆盖率只有 9.9%

`verify-refs.ps1` 的 `[4]` 原本**只解析两种写法**——块式（`文件：` + `行 A-B：`）
与"名在前"的行内式（`X.h 行 N`）。而全库绝大多数行号写成 **`（第 N 行）`**，
**完全不在解析范围内**：

```
行号引用总数 2,058
├─ 「行 N」写法      302  →  [4] 解析出 204（块式 158 + 行内式 46）
└─ 「第 N 行」写法  1,756  →  [4] 完全看不见
机器覆盖率 = 204 / 2,058 = 9.9%
```

**推论**：第九节"行号引用准确率极高（只错 9 处）"是**人工抽样**的成绩，
不是机器防线的成绩——机器防线上此前有九成区域无保护。

### 13.3 一次失败的设计（记录以免重犯）

首版补丁采用**三级启发式绑定**（同行完整路径 → 同行唯一文件名 → 同段落唯一文件名）。
跑出来报出 **30+ 处越界**，但抽查 4 例**全部是假绑定**：

| 案例 | 真相 |
|---|---|
| `types/FName.md` | 整张 API 表是一个段落（表内无空行）；表里「第 746-747 行」指 `NameTypes.h`，却绑给了段落里唯一的 `UEOps.h` |
| `modules/MovieScene-结构.md` | L91 提 `IMovieSceneModule.h`（95 行），L93-98 的「第 208 行」其实指 `.cpp` |
| `modules/Renderer-结构.md` | **一行并列 4 组「文件+行号」**，全绑给了第一个文件 → 1624 / 1481 全报越界 |
| `types/FGameplayTag.md` | 「（第 223 行）」按段落绑给了 `GameplayTagsModule.cpp`（44 行） |

**结论**：**假 FAIL 比不检查更坏**——它会诱导人去"修正"本来正确的产物。
启发式绑定全部撤除，改为**严格邻接绑定**（文件名必须紧邻数字之前）。

### 13.4 最终实现与结果

| 项 | 值 |
|---|---|
| 新增可解析形式 | `di-path`（同行的完整 `Engine/` 路径紧邻）**194** + `di-name`（同行文件名紧邻）**116** |
| 机器可绑定 | **204 → 514**（**25.0%**） |
| 如实计为 unbound | di 形式 **1,434** 处（无邻接文件名）；含全部写法合计 **1,544** 处不受检 |
| 越界检出 | **0** —— 全部 `all in range`，总判 `PASS` |

> 撤除启发式后重跑，所有"越界"报错消失——反证它们全是假绑定。
> **本轮没有抓到真实的行号错误。**

  与 **4.4「行号引用的三个口径」**；更正 4.2 措辞。
